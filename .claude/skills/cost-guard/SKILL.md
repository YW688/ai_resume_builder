# 成本闸门（cost-guard）

目标：把「一次返工 = 一次全价调用」降下来；在花钱之前，先把账算清楚。

## 何时触发

- 任何 `node scripts/hero/qwen-image-batch.mjs ... --run`
- 任何 `node scripts/hero/qwen-video-batch.mjs ... --run`
- 用户说「重新生成 / 再抽一张 / 批量出图 / 出视频 / 换 seed 再跑」

## 执行步骤（顺序固定）

1. **读清单**：`docs/hero-visual/assets.json` 里目标资产的 `model / size / duration / seed / refs`。
2. **先 dry-run**：把请求关键字段（模型、尺寸、时长、参考图数量、seed）贴给用户；不联网。
3. **给成本计划**（必须包含）：
   - 预计调用次数（图像张数 / 视频段数 × 秒数）；
   - 档位（图像 1k/2k；视频 720P/1080P、时长）；
   - 试水方案（先 1 张 1024² / 先 1 段 720P 5s）；
   - 停止条件（例如「2 次仍不满意就改提示词，不再盲抽」）；
   - 计费口径：以百炼控制台为准，不编造价格。
4. **等待用户确认**；未确认不得 `--run`。
5. **执行后记账**：把「资产 id / 模型 / 尺寸或时长 / 调用次数 / 是否返工」写入 `docs/PROJECT_RETRO_2026-10-20.md` 台账。
6. **失败重试纪律**：一次只改一个变量（提示词 / 构图 / seed）；同 seed 最多 2 次。

## 优先选择更省的路径

- 图像：先用 `qwen-image-3.0` + 1024² 试稿，定稿再用 `qwen-image-3.0-pro` + 目标尺寸。
- 视频：先 720P 5s 试机位/速度，确认后再 1080P 正式时长。
- 能用关键帧/剪辑解决的（拼接、循环、压缩、抽帧、转码），走本地脚本或剪映，不调 API。
- 提示词问题不要用「多抽几次」解决：先改约束（如手部改「插兜/遮挡」、比例写死、机位写死）。

## 输出模板

```
目标：qwen-02（1920×1080，refs×2，seed 20261102）
计划：试水 1 张 1024²（qwen-image-3.0）→ 验收 → 正式 1 张 1920×1080（pro）
预计：2 次图像调用；若返工，上限 +2 次
停止条件：2 次不满意 → 改提示词（手插兜）后再来，不盲抽
确认后执行：node scripts/hero/qwen-image-batch.mjs --only qwen-02 --run
```

## 边界

- 不替用户做「花多少」的决定；只给方案与上限。
- 不隐藏返工次数；不把「试水」说成「正式」。
- 不在未确认时执行任何 `--run`。

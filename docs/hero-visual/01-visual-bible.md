### 3.2 可读性配对（写代码前先认，验收按此测）

| 前景 / 背景 | 对比度 | 判定 |
|---|---|---|
| 云白 `#F4F8FC`（或纯白）/ `#0E1B2A`（Ink） | ≈16.3:1（纯白 ≈17.4:1） | 通过（深色遮罩上的首选） |

| 白字 / `#1A6BD6`（Sky） | ≈5.10:1 | 通过（按钮 hover/链接） |

| 白字 / `#E5355B`（Pink） | ≈4.21:1 | **不通过**常规正文；只允许大号文本（≥24 px 常规或 ≥18.66 px 粗体，按大文本 3:1） |

### 3.3 使用规则

- 一个画面**只允许这 6 个色相**（Sky / Cloud / Sunlight / Chrome / Pink / Grey-Blue；Ink 只作正文与遮罩，不算画面色相）；超出（尤其橙色皮肤、紫色天空、荧光绿）一律视为跑偏，重跑或加负向。
- 铬不要做成纯灰：要带一点点粉/蓝天色反射。
- 提示词里把 hex 写成对应物：天蓝 `#1A6BD6`=天空、云白 `#F4F8FC`=积云高光/衬衫、阳光金 `#FFE9B0`=逆光边缘、铬银 `#C9D2D9/#8E9AA4`=护栏/路面反光、珊瑚粉 `#E5355B`=极少量光晕、灰蓝 `#8E9AA1`=远景、深墨 `#0E1B2A`=剪影；**不要后期硬调**。
- 需要 UI 装饰的资产（`qwen-06` UI 贴纸页、Figma 设计层）才写「粉色发光球体 / 铬色圆环 / 玻璃面板」；hero 海报与关键帧反而要把「铬环、粉色渲光球」写进负向（见 `prompts/image/01-hero-poster.neg.txt`）。
- 前端只从这 7 个变量派生，不在组件里散落新 hex；所有 `--hero-*` 落地方式见 `04-frontend-integration.md` §3.2。

## 4. 材质与光照

### 4.1 玻璃拟态（毛玻璃卡片）

- 白色 **8%~18%** 渐变底；**1 px 白 35%** 描边；内顶高光；圆角 **24~28 px**；背后 **24~32 px** 模糊 + 饱和度提升。
- 基准 CSS（源 §2.3，可直接用）：`backdrop-filter: blur(28px) saturate(1.35) brightness(1.04)`，白底 `linear-gradient(135deg, rgba(255,255,255,.18), rgba(255,255,255,.06))`。
- 玻璃**不要做全屏磨砂**：源 §2.3 原文「卡片尺寸控制在 1100~1240 px 宽」，但同一句要求四周留出清晰视频画面，按上下文应理解为**内容容器**宽度 → 前端取 `max-width:1200px`、卡片本身 ≤640 px。若客户坚持 1100~1240 px 的卡片，需重新评估版式。
- **玻璃参数的两处源口径差异**：源 §0/§2.3 的 CSS 基准是 `blur(28px) saturate(1.35) brightness(1.04)`（前端采用这个）；旧 Figma 交付口径写的是 `blur(20px) saturate(140%)`。设计稿需按 28px/1.35 对齐，不要出现两张皮。
- 玻璃后方必须能辨认「云在动、少女在滑」，不能出现脏斑；脏斑 90% 来自：①中心高频细节 ②过度锐化 ③压缩码率太低。

### 4.2 液态铬

- 高对比环境反射；上下明暗过渡；边缘锐利；带一点粉/蓝天色反射。
- **液态铬字由设计层做**（渐变描边/图层样式），**不要让 Qwen 生成文字**：Qwen-Image 很会渲染文字，反而更容易画出假字；图片里的玻璃面板一律保持空白，文案后期前端/Figma 叠。

### 4.3 粉色渲光球

- 哑光高光 + 次表面透光感；虚焦 bokeh；尺寸 **80~400 px**；作为景深前景/背景。只用于 UI 装饰类资产（`qwen-06` / 设计层）。

### 4.4 光照

- **单一主光源**（逆光/侧逆光，太阳在画面深处），高调曝光，云层透光。
- 禁止：平光、双主光、HDR 过曝、霓虹。
- 全系列同光照方向、同色温；成片级亮度/色温对齐方法见 `03-qwen-video.md` §6.1（剪映调色/同一 LUT）。

### 4.5 视频清晰度与玻璃的因果关系（源 §2.1，保留）

`backdrop-filter: blur()` 会把底层压缩块、噪点、色带放大成「脏玻璃」，所以：

- 万相输出 **1080P MP4（H.264）**，不要 720P 拉大；天空渐变区要有 **1%~3% 颗粒**，否则大范围天空在模糊后出色带。
- 剪映/PR 导出网页版：1080p、30fps、H.264、**5~8 Mbps**、无音轨、faststart；WebM/AV1 只有本机有转码工具时才做。
- 生成阶段就避免高频细节堆在中心：中心只留云、天空、远城，主体和滑板细节放右 1/3。

## 5. 构图与「网页安全区」

### 5.1 画幅与主体位置

- 桌面 Hero 出图/出片比例 **16:9**（网页图 1920×1080；关键帧 1280×720）。
- **主体偏右**：少女占右侧 1/3；左侧 **55%~60%** 放玻璃卡片与文案。
- 安全区、主体、留白三者的关系：左侧是「给 UI 的低对比留白」，右侧是「给人物和滑板的高细节区」。

### 5.2 中心安全区（硬规则）

- **中心 60%×50% 区域**只允许：天空、云、远山、浅景深虚化；要求低对比、低细节、慢运动。
- 视频叠上 28 px 玻璃后，正文对底层对比度仍要 **≥ 4.5:1**。
- 安全区校验：在任意成片帧上叠「水平 20%~80%、垂直 25%~75%」框（即中心 60%×50%），框内不得出现文字、高对比主体、快速运动；方法见 `05-acceptance.md` B5。

### 5.3 画面内禁止

- 任何文字、字幕、水印、logo、二维码、UI 边框（毛玻璃会把它们糊成脏斑）。
- 禁止出现真人照片、第二个角色、镜面倒影里多一个人。

### 5.4 镜头运动

- **慢**：跟拍/缓推/缓摇；单个镜头内只做**一个连续动作**，不出现快速甩镜/变焦/急停，避免玻璃后方画面闪烁。量化口径见 `03-qwen-video.md` §7.2（镜头角速度 ≤8°/s）。
- 关键帧先定构图，i2v 只做「轻微推进/横移/上摇」；成片必要时放慢。

### 5.5 移动端

- 必须有 **9:16 版本**且不裁掉主体；桌面 hero 视频不要硬裁成竖屏。
- 移动端素材：`public/hero/hero-9x16.mp4`（视频，由源片 9:16 裁切 + 设计层，产物待生成）+ `public/hero/mobile-cover.jpg`（封面，`qwen-07`，产物待生成）。
- 前端兜底与 `object-position` 规则见 `04-frontend-integration.md` §3.2（移动端 object-position）与 §5.1（多源顺序）。

### 5.6 前端版式口径（唯一数值来源）

| 项 | 数值 / 规则 |
|---|---|
| 桌面断点 | ≥1024 px 用「左玻璃卡片 + 右主体」网格；<1024 px 单列、卡片靠下 |
| 网格 | `minmax(0, 1.2fr) minmax(0, 0.8fr)`（左 60% / 右 40%），容器 `max-width: 1200px` |
| 玻璃卡片 | `max-width: 640px`；内边距 `40px 36px`（移动端 `24px`）；圆角 `28px` |
| 视口高度 | `min-height: 100svh`；无横向滚动 |
| 文字 | H1 `clamp(32px, 4.2vw, 60px)`，行高 1.08，字距 -0.02em；副标 `clamp(14px, 1.3vw, 17px)`，行高 1.7 |
| CTA | 主按钮粉底白字（用 `--hero-pink-cta`），胶囊圆角；次按钮白字 + 35% 白描边 |

## 6. 统一风格词（中文自然语言锚点）

> Qwen-Image / 万相都吃中文自然语言，**不再使用旧的英文 tag 公共尾巴**。下面的措辞是**一致性锚点**，实际可粘贴文本以 `prompts/image/*.txt`、`prompts/video/*.txt` 为准；改风格必须全部文件同步，不要只改一张。

### 6.1 正向风格锚点（每张图/每段视频都要覆盖）

```text
二维动画电影质感插画，手绘背景，清晰线稿，丰富的空气透视，细腻的移轴微缩景深，极轻的胶片颗粒；新海诚式巨大积云、高调曝光、单一逆光；深钴蓝天空、奶油白云、暖金色阳光、偏冷的蓝色阴影，光晕里只有一点点克制的珊瑚粉。
```

### 6.2 负向基准（中文；每张图/每段视频都要覆盖）

```text
文字，汉字，英文字母，字幕，水印，签名，logo，二维码，UI 界面，按钮，边框；多余手指，畸形手，融合的手指，多余手臂，多余人物，两个人；帽子，鸭舌帽，棒球帽，针织帽，头饰，发带，头盔，耳机；低清，模糊，压缩噪点，色带，过曝，死白，塑料 3D 感，CG 渲染，真人照片，写实摄影；橙色皮肤，紫色天空，荧光绿；走光，偷拍视角。
```

视频镜头另加运动负向（见 `prompts/video/shot-a.neg.txt`）：镜头抖动、手持晃动、快速横摇、甩镜、快速推拉、变焦、画面撕裂、重影、拖影、人物变形、脸崩、换装/换发型、出现第二个人或第二块滑板、云层形状突然跳变、闪烁、曝光忽明忽暗、突然的剪切/转场/变速。

### 6.3 用法

- 提示词写成**自然语言句子**，允许长句；不要堆 `(tag:1.2)` 这类旧式权重语法。
- 每张图/每段视频必须明确写「**画面中不要出现任何文字、水印、logo、二维码、UI 边框**」——Qwen 很会渲染文字，这条不能省。
- 图片 I2I 提示词开头写清：「以第 1 张参考图的人物面部/服装为准，以第 2 张参考图的构图/机位为准」。
- 负向与正向都从文件读取，不做手打转抄；文件名与资产 id 的对应见 §7。

## 8. 协同规则：角色卡 → 关键帧 → i2v（源 §6 改写）

1. **先角色卡、后一切**：S2 用 Qwen-Image T2I 出 4 张正面角色卡（seed 20261020–20261023）→ 客户确认 → `design/source/refs/character_front.png`；这张脸未确认前不得批量生成。
2. **同一张脸进 I2I**：除 `qwen-06`（UI 贴纸页，T2I）与 `qwen-kf-sky`（纯天空，T2I）外，网页图与人物关键帧都用 I2I；参考图 **≤3 张**（Qwen-Image 3.0 上限）；第 1 张固定为角色卡/角色参考帧，第 2 张为构图/机位参考帧；参考帧从源片抽到 `design/source/frames/ref_*.jpg`（产物，待生成）或由剪辑截图提供。
3. **I2I 要严格听构图**：`prompt_extend=false`（否则模型会自由发挥）；提示词开头写明「以第 1 张参考图的人物面部/服装为准，以第 2 张参考图的构图/机位为准」。
4. **关键帧是视频的闸门**：关键帧必须先过 16:9 / 主体右 1/3 / 安全区 / 无文字 四关；关键帧不合格绝不跑 i2v（i2v 首帧决定成败，返工成本按秒计费）。
5. **同一套色板与措辞**：图片、关键帧、视频共用本文件的 7 色 token 与 §6 风格锚点；同一角色、同一光照方向、同一色温；**不要拿视频成片做 I2I**（压缩噪点/运动模糊会污染）。
6. **排期**：角色卡（S2）→ 7 图 + 4 关键帧（S3，可并行）→ 4 段视频（S4）→ 剪辑（S5）。视频定稿前不要锁死 hero 最终配色；API 按次计费，先各跑 1 张/1 段试水。
